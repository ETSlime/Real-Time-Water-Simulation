## 水体パーティクル描画

水のシミュレーションはパーティクル駆動型で実装されており、すべての水面表現は流体パーティクルの集合によって構築されます。流れ、衝突、蓄積などのリアルな挙動をサポートします。炎や煙などの一時的なエフェクトとは異なり、水パーティクルは継続的な寿命を持ち、シーン全体との大規模な相互作用に対応します。

### パーティクル発射ロジック（Emitter）
- 水パーティクルは `Emit()` インターフェースを通じて、Emitter によって毎フレーム発射されます。
- パーティクルは**継続的に存在する物理単位**であり、短時間で消滅することはありません。
- Cone や Box などの発射形状に対応し、初速度と初期位置が付与されます。
- `AliveList` により生存パーティクルを管理し、GPU 側では `DrawIndirect` により高効率に描画されます。

### SPH 流体システム

本システムは SPH（Smoothed Particle Hydrodynamics）に基づいています。各パーティクルは流体単位として重力・粘性・圧力などの力により移動・蓄積・衝突します。

空間インデックス構造には以下の2種類が対応しています：

#### Dense Grid（均一グリッド）
- 均一に分割されたボクセルグリッド
- 初期テストや粒子数が少ないケースに使用
- `FlattenIndex(x, y, z)` により1次元インデックスへ変換

#### Sparse Grid（スパースグリッド）
- 広範囲で疎な粒子分布に最適化された構造
- Morton 符号を用いて空間離散化とソートを実施
- すべての粒子検索と相互作用は GPU 上で完結

#### SPH スパースグリッド構築フロー

各フレームにおいて、前フレームの生存パーティクルをもとにスパースな体素構造を構築し、近傍検索の高速化を図ります：

1. CPU 側で ReadBack により、前フレームの生存パーティクルを取得します。
2. 各パーティクルの位置から体素座標を計算し、`gridMin` を更新して負の座標を防止します。
3. 各体素に対して Morton 符号を計算し、`mortonMap` にパーティクル ID を追加します。
4. `mortonMap` の要素を `TempTriplet` に変換し、Morton 符号でソートします。
5. ソート済みのリストから `SPHIndexTriplet` を構築し、同じ Morton 符号の粒子をグループ化します。
6. `SPHIndexTriplet` から `PagedIndexTripletBuffer` を生成し、GPU にアップロードします。

> 次フレーム以降、GPU 側ではこの構造を用いて効率的な近傍検索と力計算を行います：

7. 各パーティクルは `prevPosition` を用いて、前回の体素と周囲の Morton 符号を逆算します。
8. `PagedIndexTripletBuffer` により近傍ページを探索します。
9. `g_SortedIndicesSRV` を参照して粒子インデックスを取得し、`g_ParticlesUAV` から粒子データを取得して、密度・圧力・粘性などの SPH 相互作用を計算します。

#### SPH 力計算式（Pressure / Viscosity）

各フレーム、GPU は 3×3×3 の近傍探索を行い、SPH 力を計算します：

- **Wendland C2 カーネル関数** を用いて、粒子間の影響を重み付きで評価
- カーネル関数の重みを使って近傍粒子の質量を合計し、自身の密度を見積もります
- 圧力項は密度差とカーネルの勾配（`∇W`）で計算され、粒子の反発力を表します
- 粘性項は粒子間の速度差と `∇W` によりスムージングされます
- 最終的な力：
  - `pressureForce += -mass * (p_i + p_j) / 2ρ_j * ∇W`
  - `viscosityForce += viscosity * velDiff * mass / ρ_j * ∇W`
- さらに **XSPH 補正項** を加えて粒子速度を安定化させます：
  - `velocity += ε * Σ (neighbor.velocity - self.velocity) * W`

これらの計算はすべて Compute Shader によって実行され、近傍 Morton グリッド上の体素をループします。

#### Voxel Grid + 三角形衝突検出

水パーティクルは、Voxel Grid を用いた三角形衝突判定により地形とのインタラクションを行います：

- 各フレーム、Morton 符号に基づいた稀疎構造の `VoxelGrid` を構築または再利用し、静的地形三角形を格納します
- 各パーティクルは `predictedPosition` から Ray を発射します
- `RayIntersectsTriangle()` により、周囲のボクセルに含まれる三角形との交差判定を実施
- 衝突時には、法線ベクトルに基づいて反射力や滑りを計算：
  - **貫通防止**：法線に沿って反射または滑り
  - **地面スライド**：法線接線方向の速度を保持し、垂直成分を除去
- これにより、自然な下流動作・縁の蓄積・容器内の循環などが再現されます

この処理は SPH 力計算と並列に実行され、統一された流体挙動を実現します。

### 液面再構築（Marching Cubes）

水パーティクルは離散的な存在のため、連続した液面を描画するには Marching Cubes により表面メッシュを再構築する必要があります。

#### スカラーフィールドの構築

液面再構築のための Scalar Field（スカラーフィールド）は以下の2方式に対応しています：

##### Dense Grid（均一ボクセル）
- 固定サイズの3D グリッドを確保
- 毎フレーム初期化後、再累積
- `FlattenIndex(x, y, z)` による配列インデックス化
- メリット：単純構造でデバッグしやすい
- デメリット：メモリ使用量が大きく、大規模空間には不向き

##### Sparse Grid（スパースボクセル）
- 粒子周辺のみを構築対象とするスパース構造
- 各粒子が影響半径内のボクセルに対してスカラ値を累積
- **64ビット Morton 符号** を使用し、超広範囲に対応
- **ボクセル中心の Pull 型（Voxel-Centric）構築方式**：
  - 各体素が周囲粒子を探索し、重み付きで値を加算
  - 重みは距離減衰を反映し、カーネルには **Wendland C2** を使用
- 出力結果は `StructuredBuffer<float>` として GPU にアップロードされ、`InterlockedAdd` により同時書き込み対応

この構築処理は `SPHSystem` と同じ Morton インフラ・ページング構造に対応しています。

#### Marching Cubes メッシュ構築フロー

Scalar Field が構築されると、GPU 上で Marching Cubes により表面メッシュを生成します：

1. 各ボクセルセルにおいて、8 頂点の値が閾値を跨ぐかを判定
2. `g_TriTableSRV` を参照して三角形トポロジーを取得
3. 各辺の交点位置・法線を計算し、`VertexBuffer`・`IndexBuffer` に `InterlockedAdd` で書き込み
4. `DrawIndexedInstancedIndirect` を使用し描画、Cluster 分割による並列処理にも対応

重複頂点生成を避けるため、**Edge Vertex Cache** により辺のインデックスをキャッシュしています。

#### Thickness Map による液面シェーディング

液体表面の体積感とリアリズムを高めるため、スクリーンスペース厚みテクスチャ（Thickness Map）を併用しています：

- 水パーティクルの描画時に、その深度情報を厚みマップへ書き込み
- Marching Cubes で構築されたメッシュが描画時に厚みをサンプリングし、暗化や吸収表現を実現
- 以下のような演出が可能：
  - 半透明なエッジ
  - 深い領域での暗化
  - SoftParticle、境界ぼかし、泡のエフェクトなど

これらは `FluidThicknessRenderer` コンポーネントによって一括管理されています。
